# 技術指標做單建議

在設定的時段內定時取得**虛擬貨幣**、**台股**、**美股**的日線 K 線，由程式計算 EMA、MACD、RSI、ADX、ATR、費波那契與成交量，再交給 AI（Codex 或 Claude，見[共用設定](../README.md#共用設定)）綜合判斷**是否做單**；可以做單時給出進場、止盈、止損價位與原因。每個市場可以指定多個代號，或填 `AUTO` 交給 AI 從成交最熱絡的標的中挑選最多 3 個可以嘗試做單的標的。排程與 Artale 相同，以開始時間、結束時間與執行頻率（分鐘）設定，每次執行都會刪除前一次的訊息，頻道只保留最新的分析。

一律以**不開槓桿**為準：只考慮現貨買進（做多），不放空，也不使用期貨、合約或融資融券。

> **價格單位：虛擬貨幣與美股為美元，台股為新台幣。** 虛擬貨幣使用 USDT 交易對（例如 BTCUSDT），價格視同美元。

## 快速開始

先完成根目錄 README 的[環境設置](../README.md#環境設置)，以下指令皆在專案根目錄執行。

技術指標的所有設定（Webhook、排程、各市場的代號、提醒、紀錄位置）集中在 `env/signal.js`，可以直接寫註解。先複製範例：

```bash
cp env/signal.example.js env/signal.js
```

填入 Webhook 與要分析的代號，其他欄位說明見範例檔 [env/signal.example.js](../env/signal.example.js) 與[設定參考](#設定參考)：

```js
export default {
  webhooks: [
    { name: '自己的伺服器', url: 'https://discord.com/api/webhooks/xxxxxxxx/yyyyyyyy' },
  ],
  schedule: { start: '09:10', end: '22:40', intervalMinutes: 60 }, // 09:10、10:10、…、22:10
  markets: {
    crypto: { symbols: ['BTC', 'ETH', 'SNEK'] }, // 虛擬貨幣，美元（USDT）
    tw: { symbols: 'AUTO' },                     // 台股，新台幣；交給 AI 挑選
    us: { symbols: ['NVDA', 'AAPL'] },           // 美股，美元
  },
};
```

先預覽分析結果，不刪除、不發送 Discord，也不寫任何紀錄（取得行情約數秒，AI 判斷約 1 分鐘）：

```bash
npm run signal:preview
```

啟動常駐排程：

```bash
npm run signal:schedule
```

預設**每天 09:10～22:40（台灣時間）每 60 分鐘分析一次**，也就是 09:10、10:10、…、22:10，每天 14 次。啟動時如果在時段內，會先分析一次。技術指標與其他主題的排程彼此獨立，可以在不同終端機同時執行；同一個排程不要同時開兩份。

## 價格單位

| 市場 | 價格單位 | 行情來源 | 說明 |
| --- | --- | --- | --- |
| 虛擬貨幣（`crypto`） | **美元** | Binance；沒有該交易對或取得失敗時依序改用 Bybit、Bitget | 使用 USDT 交易對，例如 BTC 為 BTCUSDT；USDT 價格視同美元。只在 Bitget 上市的幣（例如 SNEK）會自動改用 Bitget |
| 台股（`tw`） | **新台幣** | Yahoo Finance | 上市（`.TW`）與上櫃（`.TWO`）自動判斷 |
| 美股（`us`） | **美元** | Yahoo Finance | |

進場、止盈、止損、現價與交給 AI 的所有指標數值，都使用該市場的單位。Discord 訊息的標題下方會註明價格單位；觀望的卡片底部顯示現價時也會加上單位，例如「現價 1747 美元」「現價 2000 新台幣」。

## 分析標的

每個市場的 `symbols` 有三種寫法：

| 寫法 | 效果 |
| --- | --- |
| 代號清單，例如 `['BTC', 'ETH']` | 分析每個代號（最多 10 個），依填寫順序顯示；每個代號都會給出「可以」或「觀望」 |
| `'AUTO'` | 從成交最熱絡的 15 個標的中，由 AI 挑選**最多 3 個**現在可以嘗試做單的標的。3 個是上限而不是目標：只有 1、2 個符合條件就只給 1、2 個；找不到符合條件的標的，或市場整體偏空、訊號不明確時**一個都不給**，顯示「目前沒有符合做單條件的標的，或市場不適合做單，建議觀望」 |
| 留空（`[]`） | 不分析這個市場，也不發送該市場的訊息；三個市場不能都留空 |

AUTO 的候選標的：

| 市場 | 候選 |
| --- | --- |
| 虛擬貨幣 | 24 小時成交額最大的 15 個 USDT 交易對（Binance，失敗時依序改用 Bybit、Bitget），排除穩定幣、包裝幣與貴金屬代幣；Binance 上追蹤股價的代幣化股票（例如 NVDAB）由 AI 排除 |
| 台股 | 前一交易日成交金額最大的 15 檔上市櫃普通股（證交所與櫃買中心 OpenAPI），不含 ETF、權證 |
| 美股 | Yahoo Finance「Most Actives」中股價 5 美元以上、成交金額最大的 15 檔股票 |

代號寫法：

| 市場 | 寫法 | 範例 |
| --- | --- | --- |
| 虛擬貨幣 | 幣種代號，大小寫不拘；`USDT` 交易對後綴會自動去掉 | `'BTC'`、`'eth'`、`'SOLUSDT'`、`'btc/usdt'` |
| 台股 | 4～6 位數字，可帶一個英文字母；`.TW`、`.TWO` 後綴會自動去掉 | `'2330'`、`'0050'`、`'6488.TWO'` |
| 美股 | 1～5 個英文字母，大小寫不拘；類別股用點號或連字號 | `'NVDA'`、`'aapl'`、`'BRK.B'` |

**0 開頭的台股代號一定要加引號**（例如 `'0050'`），否則設定檔會無法載入。代號清單也可以寫成逗號分隔文字（`'BTC,ETH'`）。

K 線固定使用**日線**（虛擬貨幣以 UTC 0 點、也就是台灣 08:00 切換；股票以交易日切換），AI 建議的持有時間約數天到數週。

## 分析方式

1. **取得 K 線**：每個標的約 500 根日線。只用**已收盤**的 K 線計算指標，尚未收盤的最後一根（今天）只用來取得現價；同一天內多次執行時，指標相同，但現價會更新，AI 會依現價重新評估進場價位。
2. **計算指標**（`src/signal/indicators.js`，參數與 TradingView 預設相同）：

   | 指標 | 內容 |
   | --- | --- |
   | EMA | EMA20、EMA50、EMA200，以及收盤價與均線的位置、均線排列 |
   | MACD(12, 26, 9) | DIF、訊號線、柱狀體（含前一根），近 10 根是否出現黃金／死亡交叉 |
   | RSI(14) | 最後一根與前一根 |
   | ADX(14) | ADX（含前一根）、+DI、−DI |
   | ATR(14) | 數值與佔現價的百分比 |
   | 費波那契 | 近 120 根的波段高低點；上升波段列出回撤位（回檔支撐）與延伸位（上方目標），下降波段列出回撤位（反彈阻力）與延伸位（下方目標） |
   | 成交量 | 最後一根與前 20 根平均的倍數 |

   另外附上最近 5 根 K 線與近 20 根的最高、最低價。
3. **AI 判斷**：把所有標的的指標交給 AI（不需要網路搜尋），依下列規則判斷：
   - 只有在趨勢、動能與成交量多數支持上漲，且**風險報酬比（止盈 − 進場）÷（進場 − 止損）至少 1.5** 時才給「可以」，否則「觀望」。
   - 止損設在關鍵支撐下方並參考 ATR（一般距離進場價 1～2 倍 ATR）；止盈參考前高、阻力位或費波那契延伸位。
   - 原因必須引用具體的指標數值；其他事項（例如撤單條件）選填。
4. **檢查 AI 的回覆**：價位依現價的位數四捨五入。「可以」但價位不合理時（不是正數、不符合「止損 < 進場 < 止盈」、進場價與現價相差超過 20%），改為「觀望」並在原因中註明；AUTO 則捨棄該標的。指定的代號 AI 沒有回覆時，顯示為觀望。

調整判斷規則請修改 `src/signal/signals.js` 的 `buildSignalPrompt()`。

**此通知為 AI 自動生成，不構成投資建議。** 技術指標只反映過去的價格與成交量，無法預測消息面與突發事件；實際交易請自行判斷並控制風險。

## Discord 發布內容

每個市場發送一則訊息，標題下方以小字註明 K 線週期與價格單位；每個標的一張卡片，**可以做單為綠色、觀望為灰色**、無法取得行情為紅色。卡片內每行以「圖示 小標題：」開頭，進場、止盈、止損的價位以程式碼格式凸顯。最後一則訊息是黃色的免責聲明卡片。

以下為 Discord 上的顯示示意（`┃` 為卡片左側的顏色條，`` ` `` 包住的價位會以灰底等寬字顯示）：

```text
## 🪙 虛擬貨幣技術分析｜2026-11-20（週五）
-# 🕒 日線・💵 價格單位：美元（USDT 交易對）
🟩┃ 🏷️ 標的：BTC，是否做單：🟢 可以
🟩┃ 💰 進場：`62000`，止盈：`65000`（+4.8%），止損：`60000`（-3.2%）
🟩┃ 📊 原因：EMA20 > EMA50 > EMA200 多頭排列，MACD 柱狀體由負轉正……
🟩┃ 📝 其他事項：若跌破 60500，則直接撤單
🟩┃ 資料來源：Binance BTCUSDT

⬜┃ 🏷️ 標的：ETH，是否做單：⚪ 觀望
⬜┃ 📊 原因：收盤價低於三條 EMA，ADX 42.8、−DI 高於 +DI，跌勢仍強……
⬜┃ 現價 1747 美元・資料來源：Binance ETHUSDT

## 🇹🇼 台股技術分析｜2026-11-20（週五）
-# 🕒 日線・💵 價格單位：新台幣・🤖 AUTO：由 AI 從上市櫃普通股中前一交易日成交金額最大的 15 個標的中挑選最多 3 個
🟩┃ 🏷️ 標的：2330 台積電，是否做單：🟢 可以
🟩┃ 💰 進場：`1985`，止盈：`2150`（+8.3%），止損：`1900`（-4.3%）
🟩┃ 📊 原因：……
🟩┃ 資料來源：Yahoo Finance 2330.TW

🟨┃ ⚠️ 此通知為 AI 自動生成，不構成投資建議
🟨┃ 技術指標僅反映過去的價格與成交量，實際交易請自行判斷並控制風險
```

- 標的名稱與「可以／觀望」以粗體顯示；可以為 🟢、觀望為 ⚪。
- 可以做單時只顯示**進場價**，不顯示現價，避免兩個價位混淆；止盈、止損後的百分比是相對於進場價的漲跌幅。
- 觀望時不顯示進場、止盈、止損，只寫原因，現價顯示在卡片底部；其他事項沒有內容時不顯示。
- AUTO 沒有挑出任何標的時，顯示一張灰色卡片「💤 目前沒有符合做單條件的標的，或市場不適合做單，建議觀望」。
- 指定的代號無法取得行情（例如代號錯誤、行情網站連線失敗）時，該代號顯示紅色卡片，以「❌ 原因」說明，其他代號照常分析。
- 免責聲明為一張黃色卡片，聲明文字以粗體顯示，卡片底部以小字補充說明。
- 圖示、顏色與文字都在 `src/signal/format.js` 調整。

每次執行的發送順序：

1. 取得行情、計算指標並由 AI 判斷。**所有標的都無法取得行情或 AI 失敗時不刪除舊訊息**，頻道保留前一次的內容。
2. 刪除前一次發送的訊息。訊息已被手動刪除（Discord 回傳 404）時略過；其他刪除失敗時**不發送這次的內容**，等下一個排程時間。
3. 發送最新的分析，並記錄訊息 ID，供下一次刪除。

只會刪除技術分析流程自己發送、記錄在 `data/signal/state.json` 的訊息；用 `npm run signal:webhook` 手動發送的訊息不會被自動刪除。

## 預覽與手動操作

```bash
# 預覽：分析並印出 Discord JSON，不刪除、不發送、不寫紀錄
npm run signal:preview

# 立即分析並發送一次（不受排程星期與時間限制）：先刪除前一次的訊息，再發送最新的分析
npm run signal
```

手動新增、修改、刪除或查詢訊息，固定使用 `env/signal.js` 的 `webhooks` 與 `files.discordMessages`，用法與[共用 Webhook 工具](../README.md#共用-webhook-工具)相同：

```bash
npm run signal:webhook -- --help
npm run signal:webhook -- list
```

## 自動排程

修改 `env/signal.js`、`env/.env.shared` 或程式後，需重新啟動常駐程式才會載入新設定。排程在 `env/signal.js` 的 `schedule` 設定：

寫法與 Artale 的排程相同：在指定星期的 `start`～`end` 之間，從 `start` 起每隔 `intervalMinutes` 分鐘分析一次，每次都先刪除前一次的訊息再發送最新的分析。

```js
schedule: {
  days: '1-7',            // 1=週一，7=週日；只在平日發送可寫 '1-5'
  start: '09:10',         // 每天開始時間
  end: '22:40',           // 每天結束時間（不支援跨越午夜）
  intervalMinutes: 60,    // 執行頻率（分鐘）
  timeZone: 'Asia/Taipei',
},
```

例如預設的 `start: '09:10'`、`end: '22:40'`、`intervalMinutes: 60` 會在 09:10、10:10、…、22:10 每小時執行一次（下一次 23:10 已超過結束時間，所以最後一次是 22:10）；`intervalMinutes: 240` 則是 09:10、13:10、17:10、21:10。`start` 與 `end` 相同時每天只執行一次。每次執行都會呼叫一次 AI，頻率越高，AI 用量越多。

### 各市場的交易時間（台灣時間）

設定時段時可參考各市場的開盤與收盤時間：

| 市場 | 開盤 | 收盤 | 說明 |
| --- | --- | --- | --- |
| 虛擬貨幣 | 24 小時交易 | 日線每天 08:00 換日 | 日線以 UTC 0 點（台灣 08:00）收盤 |
| 台股 | 週一～週五 09:00 | 13:30 | 國定假日休市 |
| 美股（夏令時間） | 21:30 | 隔天 04:00 | 3 月第二個週日～11 月第一個週日；美國時間週一～週五 09:30～16:00 |
| 美股（冬令時間） | 22:30 | 隔天 05:00 | 11 月第一個週日～3 月第二個週日 |

指標使用已收盤的日線，同一根日線收盤前，多次執行的指標都相同，只有現價會更新：

| 想要的效果 | 建議時段 |
| --- | --- |
| 每個市場都用最新收盤的日線，每天一次 | 08:05 執行一次（`start`、`end` 都設 `'08:05'`）：虛擬貨幣剛換日、美股已收盤；台股使用前一個交易日的日線 |
| 台股也用當天收盤的日線 | 時段涵蓋 13:30 之後，例如 14:05 再執行一次 |
| 盤中依現價更新進場建議 | 台股盤中 09:00～13:30；美股盤中為台灣晚上，時段不能跨越午夜，最晚只能涵蓋到 23:59 |

| 情況 | 處理方式 |
| --- | --- |
| 啟動時在時段內 | 先分析一次，之後依排程時間執行 |
| 啟動時在時段外 | 等到下一個排程時間（例如隔天的開始時間） |
| 電腦睡眠到時段結束後才喚醒 | 略過錯過的那次，等下一個排程時間 |
| 執行失敗（行情、AI、網路或 Discord 錯誤） | 記錄錯誤，前一次的訊息保留在頻道上，等下一個排程時間再執行 |

股票在交易時段中執行時，當天尚未收盤的 K 線不會用來計算指標，只用來取得現價。

需要保持執行時，可使用 `tmux` 或 `pm2`，例如：

```bash
pm2 start npm --name signal -- run signal:schedule
```

## 多個 Webhook 與變更提醒

`webhooks` 可以列出多個 Webhook，寫法與規則和 Crypto 相同，見 Crypto 文件的[多個 Webhook](crypto.md#多個-webhook)：行情只分析一次，再依清單順序發送到每個 Webhook；每個 Webhook 各自刪除自己前一次的訊息。

每個 Webhook 也可以設定 `webhookProfile`（`personaPrompt`、`avatarMessage`、`nameMessage`），在名稱或頭像被更換時發送提醒，規則見 Crypto 文件的 [Webhook 名稱與頭像變更提醒](crypto.md#webhook-名稱與頭像變更提醒)。技術指標的記錄存在 `data/signal/webhook-profiles/<Webhook ID>.json`，與其他主題分開；AI 感想使用設定檔的 `aiTimeoutMs` 逾時設定。

## 設定參考

技術指標的所有設定集中在 `env/signal.js`（範例見 [env/signal.example.js](../env/signal.example.js)），以 `export default` 匯出設定物件；除了 `webhooks` 以外都是選填，未填寫時使用預設值。欄位名稱寫錯、型別不符或代號格式錯誤時，程式會指出設定檔與欄位名稱並停止。

共用的 AI 設定（`AI_PROVIDER`、執行檔、模型、API key）放在 `env/.env.shared`，見[根目錄 README](../README.md#共用設定)。系統環境變數不會覆寫技術指標設定；只有 `SIGNAL_CONFIG_FILE` 可用來改用其他設定檔。

| 欄位 | 預設值 | 用途 |
| --- | --- | --- |
| `webhooks` | 無 | Webhook 清單，正式發送至少要一個；預覽不需要 |
| `webhooks[].webhookProfile` | 全部空白 | 該 Webhook 的名稱與頭像變更提醒，見[多個 Webhook 與變更提醒](#多個-webhook-與變更提醒) |
| `schedule.days` | `'1-7'` | 發送的星期 |
| `schedule.start` | `'09:10'` | 每天開始時間 |
| `schedule.end` | `'22:40'` | 每天結束時間；不能早於開始時間（不支援跨越午夜） |
| `schedule.intervalMinutes` | `60` | 執行頻率（分鐘）：從開始時間起每隔幾分鐘分析一次 |
| `schedule.timeZone` | `'Asia/Taipei'` | 排程與訊息時間使用的時區 |
| `markets.crypto.symbols` | `['BTC', 'ETH']` | 虛擬貨幣代號（價格單位：美元，USDT 交易對）、`'AUTO'` 或 `[]`（不分析） |
| `markets.tw.symbols` | `['2330', '2345']` | 台股代號（價格單位：新台幣）、`'AUTO'` 或 `[]`（不分析） |
| `markets.us.symbols` | `['NVDA', 'AAPL']` | 美股代號（價格單位：美元）、`'AUTO'` 或 `[]`（不分析） |
| `aiTimeoutMs` | `600000`（10 分鐘） | AI 判斷的逾時時間；不使用共用的 `AI_TIMEOUT_MS` |
| `files.state` | `'data/signal/state.json'` | 每個 Webhook 目前在頻道上的訊息 ID，下次執行時先刪除 |
| `files.discordMessages` | `'data/signal/discord-messages.jsonl'` | 訊息操作紀錄 |

K 線固定使用日線，`markets` 的每個市場只有 `symbols` 一個欄位。`markets` 中沒有寫到的市場使用預設值；不想分析某個市場時，把它的 `symbols` 設為 `[]`。紀錄檔的相對路徑以專案根目錄為準。

## 問題排查

Node、AI CLI 與 Webhook 的共用問題，見[共用問題排查](../README.md#問題排查)。

| 現象 | 處理方式 |
| --- | --- |
| 尚未設定 Webhook | 確認 `env/signal.js` 的 `webhooks` 已填入至少一個 Webhook |
| 「markets.xxx.symbols 格式錯誤」 | 依[代號寫法](#分析標的)修正；0 開頭的台股代號要加引號 |
| 「schedule 有不支援的欄位：time」或「markets.xxx 有不支援的欄位：interval」 | 舊版設定：`time` 改為 `start`、`end`、`intervalMinutes`；刪除 `interval`（固定使用日線） |
| 「填 AUTO 時不能再加其他代號」 | `AUTO` 要單獨使用，例如 `symbols: 'AUTO'` |
| 「至少要有一個市場的 symbols 填寫代號或 AUTO」 | 三個市場都設成了 `[]`，至少保留一個 |
| 卡片顯示「無法取得行情資料」 | 確認代號正確（虛擬貨幣需在 Binance、Bybit 或 Bitget 其中一個有 USDT 現貨交易對；台股、美股需在 Yahoo Finance 查得到）；連線問題時稍後以 `npm run signal` 重新發送 |
| 「Binance：HTTP 451」 | 所在地區無法使用 Binance API，會自動依序改用 Bybit、Bitget；三者都無法使用時無法分析虛擬貨幣 |
| 「Yahoo Finance：HTTP 429」 | 被限制請求頻率，程式會自動重試一次；仍失敗時稍後再執行 |
| 「所有標的都無法取得行情資料」 | 網路或行情網站異常，這次不發送也不刪除舊訊息；等下一個排程時間再執行 |
| AUTO 一直顯示「目前沒有符合做單條件的標的」 | 行情偏空或訊號不明確時正常；AI 只在風險報酬比至少 1.5 且多數指標支持時才挑選，不會為了湊數硬給 |
| 原因中出現「AI 給出的價位不合理，改為觀望」 | AI 的價位不符合「止損 < 進場 < 止盈」或離現價太遠，程式已改為觀望 |
| AI 逾時 | 調高設定檔的 `aiTimeoutMs`，或減少代號數量 |
| 每次都顯示讀取狀態檔失敗 | 紀錄檔損壞；確認內容或移除 `data/signal/state.json`（移除後前一次的訊息不會被自動刪除） |

## 運作機制與開發

### 設定與紀錄位置

```text
env/
├── signal.example.js           # 技術指標設定檔範例
└── signal.js                   # 技術指標正式設定檔，不納入版本控制
data/signal/
├── state.json                  # 每個 Webhook 目前在頻道上的訊息 ID（下次執行時先刪除）

└── webhook-profiles/           # 每個 Webhook 名稱與頭像的上次記錄，用來偵測更換
```
